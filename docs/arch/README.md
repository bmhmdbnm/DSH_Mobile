# 代码架构快照

> 面向：实现者 · 状态：stable（随 2026-10-11 的 v001 建立）

这份目录保存 DSH Mobile 的**自动生成**架构快照：把仓库里各模块的实际依赖关系扫出来，
渲染成一张离线可看的交互页面，用来回答"现在的架构长什么样、谁依赖谁、哪里成环"。
手绘的架构说明在 [ARCHITECTURE.md](../ARCHITECTURE.md)，那份讲的是设计意图，这份讲的是代码实际状态。

## 怎么生成

```bash
npm run arch                        # 生成下一版（v001、v002…）
npm run arch -- --note "重构会话列表"  # 给这一版记一句话
npm run arch -- --version v003      # 指定版本目录（已存在则覆盖）
npm run arch -- --json              # 只打印汇总，不写文件
```

生成后打开 `docs/arch/index.html`（浏览器停在这里刷新即可，它永远是最新一版）。

## 目录约定

| 路径 | 内容 | 是否变化 |
|---|---|---|
| `index.html` | **最新一版**快照 | 每次生成都覆盖 |
| `latest.json` | 最新版本号、时间、commit | 每次生成都覆盖 |
| `vNNN/index.html` | 该版本的归档副本 | 生成后不再变 |
| `vNNN/graph.json` | 该版本的原始扫描结果（节点、边、指标） | 同上 |
| `vNNN/diff.json` | 与上一版的依赖边增删 | 同上 |

版本号三位递增；`vNNN/graph.json` 是逐版对比的依据，页面上的"与上一版相比"一节读的就是它。

## 页面怎么读

- 顶部固定显示 commit、分支、生成时间、未提交改动数：**先确认这三个值再看图**，否则可能在看旧快照。
- 左上按层分带，一带有向图从左到右是"被依赖 → 依赖"。点任意模块，右侧列出它的文件、行数、
  声明类型、import 清单，以及"它依赖谁""谁依赖它"。
- 工具条可按层过滤（iOS App / iOS Kit / JS / Python），也可只看环。

图例与口径：

| 线型 | 含义 | 可靠性 |
|---|---|---|
| 实线灰 | Swift `import` 自有模块、SPM target 依赖、JS/Python 相对 import | 权威 |
| 黄虚线 | Swift 跨目录的**类型引用** | 启发式，会漏也会误，可一键关掉 |
| 红虚线 | 循环依赖（Tarjan 强连通分量） | 权威 |

## 已知误差与边界

1. **启发式边不可当结论用。** 它靠"类型名唯一声明在某个分组"来推断跨目录引用，已剔除注释、
   字符串，并要求类型出现在类型标注、泛型、构造调用等语法位置；但泛型参数遮蔽、同名局部量
   仍可能造成误判。页面上每条启发式边都带具体类型名，用于人工判断。
2. **不做函数级。** 节点是模块（目录）级，模块内部的文件依赖不画，只计入规模。
3. **结构性不可能的边直接丢弃。** 例如库模块反向依赖 App target，命中即说明启发式在猜；
   丢弃条数记在 `graph.json` 的 `meta.droppedEdges` 里。
4. **Swift App target 不在 SPM 里。** App 的边界来自 Xcode target 与目录约定，
   `swift package describe` 只能覆盖 DSHKit / RelayKit 两个 target。
5. 数字会漂。文件数、行数、边数都随代码变化，引用时以页面上标注的 commit 为准。
